Architecture Reference Document #04

Cypher & Knowledge Graph Modeling Cheat Sheet

Standardized property graph patterns, syntax, and AML detection queries for Neo4j.

1. The Property Graph Anatomy

Unlike relational tables that link entities via foreign keys, a Property Graph stores explicit pointers:

  • Nodes: The entities (e.g., (:Person), (:Company), (:Account), (:Address)).
  • Labels: The type tags on nodes (can have multiple labels, e.g., :Person:PEP:Sanctioned).
  • Relationships (Edges): Directed connections (e.g., -[:BENEFICIAL_OWNER_OF]->, -[:TRANSFERRED]->).
  • Properties: Key-value metadata on both nodes and edges (e.g., {amount: 50000, currency: "USD", timestamp: "2024-09-12"}).

2. Core Cypher AML Query Patterns

Investigation Pattern Cypher Query Pattern What It Detects
Direct Beneficial Ownership 
MATCH (p:Person {id: 'P_901'})-[:BENEFICIAL_OWNER_OF]->(c:Company)
RETURN p.name, c.name, c.jurisdiction
 Identifies all corporate entities controlled by a specific individual.
Shared Physical Address (Shell Factory) 
MATCH (c1:Company)-[:REGISTERED_AT]->(a:Address)<-[:REGISTERED_AT]-(c2:Company)
WHERE c1 <> c2
RETURN a.street, count(DISTINCT c1) AS shell_count
ORDER BY shell_count DESC
 Uncovers registered office addresses hosting dozens of distinct shell companies.
Multi-Hop Money Trails (1 to 5 Hops) 
MATCH path = (origin:Account {id: 'ACC_START'})-[:TRANSFERRED*1..5]->(dest:Account)
WHERE dest.is_sanctioned = true
RETURN path
 Traces layered wire transfers across up to 5 intermediary mule accounts.
Circular Transactions (Layering Rings) 
MATCH path = (a:Account)-[:TRANSFERRED*2..6]->(a)
RETURN [n in nodes(path) | n.id] AS ring, length(path) AS hops
 Detects money laundering loops where funds return to the originator after laundering.
