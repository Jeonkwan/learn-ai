Lesson 0009 • Production Infrastructure

Vertex AI Vector Search in Production

A DevOps guide to Indexes, Endpoints, Streaming updates, and VPC Peering.

Now that we understand how ScaNN indexes high-dimensional vectors, how do you actually deploy, operate, and maintain this in Google Cloud? For a DevOps engineer, Vertex AI Vector Search introduces a distinct 3-tier architectural hierarchy.

The 3-Tier Resource Hierarchy

[Tier 1: Cold Storage Data] Cloud Storage Bucket (gs://aml-embeddings/data.jsonl) • Stores raw JSONL records: {"id": "chunk_042", "embedding": [...], "restricts": [...]} │ ▼ (Trigger Index Build via gcloud / API) [Tier 2: The Compiled Index] Vertex AI Index (projects/123/locations/us-central1/indexes/456) • The compiled ScaNN binary data structure (cannot serve queries directly) │ ▼ (Deploy to Serving Cluster) [Tier 3: The Live Serving Cluster] Vertex AI Index Endpoint (projects/123/locations/us-central1/indexEndpoints/789) • Hosts the DeployedIndex on managed GCE nodes (e.g., e2-standard-16) • Serves live sub-5ms queries over Private Service Connect (PSC) or VPC Peering

Batch Updates vs. Streaming Updates

When creating a Vector Search index in GCP, you must choose the update mode up front:

  • Batch Update (Static Index): You dump files to Cloud Storage and trigger an index build. Best for historical case backfills. Rebuilding an index of 10M items takes 30–60 minutes, but produces the highest query throughput and lowest storage cost.
  • Streaming Update (Dynamic Index): Allows inserting, updating, or deleting individual vectors via a real-time API in milliseconds. Essential for live AML monitoring systems where new incoming wire transfers must be searchable immediately.

Production Networking: Keeping Banking Data Private

Financial crime and banking data must never traverse the public internet. Vertex AI Vector Search provides two enterprise networking modes:

  1. VPC Network Peering: Direct peering between your organization's custom VPC and Google's internal service network.
  2. Private Service Connect (PSC): Exposes the Vector Search endpoint as a private IP address (forwarding rule) inside your own subnet. This is the modern GCP best practice because it eliminates IP address overlap conflicts.

DevOps Sizing & Deployment Command

Deploying a compiled index to an endpoint using the gcloud CLI:

gcloud ai index-endpoints deploy-index ENDPOINT_ID \
  --region=us-central1 \
  --index=INDEX_ID \
  --deployed-index-id=aml_cases_deployed_v1 \
  --display-name="AML Case Narrative Index" \
  --min-replica-count=2 \
  --max-replica-count=5 \
  --machine-type=e2-standard-16
High Availability Rule
Always set --min-replica-count=2 in production. Google Cloud automatically distributes replicas across separate availability zones to guarantee continuous uptime during platform maintenance.
