Architecture Reference Document #02

Vector Pipelines: Chunking, Embeddings & ANN Indexing

A quick reference on chunking trade-offs, vector geometries, and Google Cloud Vertex AI Vector Search.

1. Document Chunking Strategies

Chunking controls the granularity of information injected into the LLM context window. Choosing the wrong strategy leads to either loss of context (chunks too small) or diluted embeddings (chunks too big).

Strategy Typical Parameters Best Used For Trade-offs & Failure Modes
Fixed-Size Window 512 tokens / 50 overlap Quick prototyping, uniform tabular text Cuts sentences mid-thought; fractures semantic relationships across chunk boundaries.
Recursive Character Separators: ["\n\n", "\n", " ", ""] Investigator narratives, SAR reports, legal filings Industry standard. Respects paragraphs and sentences before falling back to arbitrary character splits.
Semantic Chunking Dynamic cosine distance threshold across adjacent sentences Unstructured depositions, conversational transcripts Computationally expensive; triggers multiple embedding calls during ingestion.
Hierarchical / Parent-Child Child: 128 tokens
Parent: 1024 tokens		 Complex regulatory guidelines, dense case law Best retrieval precision: searches small child chunks, but injects the larger parent passage into the LLM.

2. Vector Embeddings & Distance Metrics

An embedding model encodes a text chunk into a fixed-length coordinate array (e.g. 768 dimensions for text-embedding-004 or 1536 for OpenAI text-embedding-3-small).

Distance Metric Mathematical Formula When to Select
Cosine Similarity cos(θ) = (A • B) / (||A|| × ||B||) Standard for text retrieval. Measures the directional angle, ignoring text length discrepancies.
Dot Product (Inner Product) A • B = ∑ (Ai × Bi) Use when embeddings are unit-normalized (length = 1.0). Computationally faster than full cosine division.
Euclidean Distance (L2) d = √∑(Ai - Bi)2 Used when geometric magnitude matters (less common in NLP, common in image/spatial models).

3. ANN Indexing Engines (GCP / Vertex AI vs HNSW)

Algorithm / Engine Core Mechanism DevOps / Infrastructure Characteristics
ScaNN
(Google Vertex AI Vector Search)		 Quantization with Score-Aware Loss + Anisotropic Vector Quantization Massive QPS, sub-5ms p99 latency, native serverless or dedicated endpoints in GCP. Optimized for extreme scale (millions to billions).
HNSW
(Hierarchical Navigable Small World)		 Multi-layer proximity graphs (similar to skip-lists in graph form) High recall (>98%), fast queries. Memory-intensive because the entire graph structure must reside in RAM. Default in Qdrant, Milvus, and pgvector.
IVF-PQ
(Inverted File + Product Quantization)		 K-means clustering + 8-bit vector compression Drastically cuts memory consumption by 80–90%, but sacrifices a small amount of recall accuracy.
