The Unstructured Data Dilemma

Why LLMs cannot hold everything in RAM, and the architectural divide between Vectors and Graphs.

As a DevOps and systems engineer, you are familiar with a classic tradeoff: you don't load an entire 500-gigabyte database table into active memory every time a web query comes in; you build indexes and query the right slice.

When working with Large Language Models (LLMs), engineers confront an identical challenge. In financial crime investigation, an anti-money laundering (AML) unit generates thousands of unstructured artifacts: Suspicious Activity Report (SAR) narrative PDFs, KYC corporate filings, court depositions, and internal analyst memos. How do we make this avalanche of text accessible to an LLM?

The Naive Temptation: "Just Stuff It In The Prompt"
Modern models boast 1M+ token context windows. Why not just pass the entire archive to Gemini or GPT-4?
  • Latency: Processing 500k tokens takes 15–30 seconds per query, ruining real-time analysis.
  • Cost: Paying $5 to $15 per investigator question drains cloud budgets within weeks.
  • "Lost in the Middle": Models suffer from attention degradation when needle facts sit in giant document dumps.

The Architectural Solution: External Memory

To provide unstructured data efficiently, we separate computation (the LLM) from storage (the index). This pattern is called Retrieval-Augmented Generation (RAG). When a user asks a question, our pipeline retrieves only the 3 to 10 most relevant pieces of context and feeds them into the model's immediate prompt.

However, unstructured data in financial crime contains two radically different kinds of information:

1. The Vector Route (Fuzzy Semantics)

Mechanism: Slices text into chunks and converts each chunk into high-dimensional coordinates (an embedding). Retrieval finds chunks that share conceptual meaning.

Ideal for: Fuzzy textual questions.

"Show me past investigator write-ups describing layering schemes using luxury watch purchases."

Fatal Flaw: Blind to relational structure. It cannot trace a multi-hop path across five companies to find the ultimate beneficial owner.

2. The Graph Route (Deterministic Topology)

Mechanism: Extracts entities (Person, Shell Corp, Bank Account) as Nodes and connections as directed Edges ([:TRANSFERRED], [:OWNS]) in a database like Neo4j.

Ideal for: Network & relational questions.

"Which shell companies share the same registered address in Cyprus and sent funds to Account 9901?"

Fatal Flaw: Loses unstructured narrative nuance (e.g., subtle tone or investigator hunches) that was not turned into graph nodes.

The Modern Synthesis: Hybrid / GraphRAG

In mature financial crime systems, neither alone is sufficient. We build Hybrid Systems (GraphRAG):

  1. Vector Search retrieves relevant narrative context (e.g., police reports, interview memos).
  2. Graph Traversal (Cypher) reveals structural connections (e.g., hidden ownership syndicates, circular money flows).
  3. The LLM synthesizes both into an actionable briefing for the investigator.
Architectural Rule of Thumb
If the question hinges on "What does this text talk about?" → Reach for Vector Search.
If the question hinges on "How are these entities connected across hops?" → Reach for a Knowledge Graph.

Primary Source Recommendation

Read the seminal paper introducing RAG to the world:

• Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks (Lewis et al., 2020).
