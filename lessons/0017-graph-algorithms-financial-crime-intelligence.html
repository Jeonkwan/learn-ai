Lesson 0017 • Graph Data Science

Graph Algorithms for Financial Crime Intelligence

Uncovering hidden fraud syndicates and mule coordinators using PageRank and Community Detection.

Targeted Cypher queries work well when an investigator already suspects a specific individual. But how does an intelligence unit proactively discover organized criminal networks hidden across millions of bank accounts?

We use Graph Data Science (GDS) Algorithms. Instead of inspecting nodes one by one, graph algorithms analyze the global topology of the network to calculate risk scores and cluster criminal syndicates.

The Two Essential AML Algorithm Families

1. Centrality: Finding the Mastermind

In a money mule syndicate, the true coordinator rarely transfers money directly to victims. Instead, hundreds of low-level mules send funds through intermediary brokers.

  • PageRank: Measures transitive influence. Accounts that receive funds from other high-volume accounts score higher.
  • Betweenness Centrality: Calculates how often a node sits on the shortest path between all other nodes in the network. A high score flags the vital "bridge" or broker coordinating disparate fraud rings.

2. Community Detection: Unmasking Syndicates

Criminal organizations frequently operate in tightly knit rings that share phone numbers, IP addresses, and device fingerprints to orchestrate synthetic identity fraud.

  • Louvain / Leiden Algorithm: Partitions the graph into modular clusters where internal connections are far denser than expected by chance.
  • Weakly Connected Components (WCC): Discovers isolated sub-networks operating independently from legitimate retail banking traffic.

Running Louvain Community Detection in Neo4j GDS

In Neo4j, running community detection requires just a single procedure call:

// 1. Project the in-memory graph projection
CALL gds.graph.project(
  'transferNetwork',
  'Account',
  'TRANSFERRED',
  { relationshipProperties: 'amount' }
);

// 2. Execute Louvain algorithm and write communityId back to nodes
CALL gds.louvain.write('transferNetwork', {
  writeProperty: 'communityId'
})
YIELD communityCount, modularity;

// 3. Find the largest suspicious rings
MATCH (a:Account)
RETURN a.communityId, count(a) AS cluster_size, sum(a.total_volume) AS ring_volume
ORDER BY ring_volume DESC
LIMIT 10;
