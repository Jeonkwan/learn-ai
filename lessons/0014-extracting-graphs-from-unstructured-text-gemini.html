Lesson 0014 • Graph Extraction

Extracting Graphs from Unstructured Text

Using Gemini's structured JSON output mode to extract verifiable entity triples from investigative narratives.

A graph database is only as useful as the entities and edges inside it. In a bank, structured transactions already live in databases, but the most damning evidence—who actually controls the company, family ties, and side agreements—is buried in unstructured text (whistleblower emails, police tips, and investigator notes).

How do we automatically transform unstructured narrative paragraphs into clean, typed graph nodes and edges?

The Knowledge Extraction Triple: (Subject, Predicate, Object)

Every relationship in a knowledge graph can be represented as an RDF/Property Triple:

Raw Text: "Viktor Orlov registered BlueSky Trading in Cyprus and transferred $2M to Swiss Account 401." │ ▼ (Information Extraction via LLM) Triple 1: (:Person {name: "Viktor Orlov"}) ──[:REGISTERED]──► (:Company {name: "BlueSky Trading", jurisdiction: "CY"}) Triple 2: (:Company {name: "BlueSky Trading"}) ──[:TRANSFERRED {amount: 2000000, currency: "USD"}]──► (:Account {iban: "CH99401"})

Using Gemini 1.5 Structured Output (JSON Schema)

If you ask an LLM in plain English: "Extract the entities and relationships", it might return poetic bullet points or messy text that crashes your automated ingestion script.

In production pipelines on Vertex AI, we enforce Controlled Generation by passing a strict response_schema. This guarantees the model outputs valid, typed JSON matching our schema:

curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://us-central1-aiplatform.googleapis.com/v1/projects/${PROJECT_ID}/locations/us-central1/publishers/google/models/gemini-1.5-flash:generateContent" \
  -d '{
    "contents": [{
      "role": "user",
      "parts": [{ "text": "Extract entities and relationships from: Whistleblower reported that Sergei K. secretly controls Novatech via nominee Olga S." }]
    }],
    "generationConfig": {
      "responseMimeType": "application/json",
      "responseSchema": {
        "type": "OBJECT",
        "properties": {
          "nodes": {
            "type": "ARRAY",
            "items": {
              "type": "OBJECT",
              "properties": {
                "id": { "type": "STRING" },
                "label": { "type": "STRING", "enum": ["Person", "Company", "Account"] },
                "name": { "type": "STRING" }
              },
              "required": ["id", "label", "name"]
            }
          },
          "edges": {
            "type": "ARRAY",
            "items": {
              "type": "OBJECT",
              "properties": {
                "source_id": { "type": "STRING" },
                "target_id": { "type": "STRING" },
                "type": { "type": "STRING" }
              },
              "required": ["source_id", "target_id", "type"]
            }
          }
        }
      }
    }
  }'

Loading the Output into Neo4j via Cypher MERGE

Once your Cloud Run ingestion worker receives the validated JSON payload, it converts the entities into idempotent Cypher statements using MERGE (which inserts the node if it doesn't exist, or updates it if it does):

MERGE (p:Person {name: "Sergei K."})
MERGE (c:Company {name: "Novatech"})
MERGE (p)-[:BENEFICIAL_OWNER_OF]->(c);
