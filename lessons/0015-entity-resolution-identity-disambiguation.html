Lesson 0015 • Identity Resolution

Entity Resolution & Identity Disambiguation

Preventing fractured knowledge graphs when bad actors deliberately disguise their names and corporate filings.

Financial criminals rarely conduct money laundering under a single, consistent name. In corporate registries and wire memos, you will encounter intentional variations:

  • Document 1: "Alexandre Vance" (DOB: 12/04/1974, Address: Limassol, Cyprus).
  • Document 2: "A. Vance" (Director of Ocean Shipping Ltd).
  • Document 3: "Vance, Alexander" (Beneficial owner of Swiss Account #9081).

If your extraction pipeline blindly creates a new node every time a slightly different string appears, your knowledge graph becomes fractured into isolated islands. A Cypher query searching for a path between Alexandre Vance and Swiss Account #9081 will return zero paths, completely missing the money laundering scheme!

The Three Stages of Entity Resolution (ER)

[Disparate Extracted Entities] "Alexandre Vance" "A. Vance" "Vance, Alexander" │ │ │ ▼ ▼ ▼ [STAGE 1: Deterministic Hard Attribute Blocking] • Match on exact Tax IDs, Passport Hashes, or LEI Corporate Identifiers │ ▼ (If Hard IDs are missing or obscured) [STAGE 2: Fuzzy String & Phonetic Matching] • Jaro-Winkler String Distance (> 0.88) + Soundex/Metaphone Phonetic Equivalence │ ▼ [STAGE 3: Graph Topology Correlation] • Do both entities share the same registered address, phone number, or bank branch? │ ▼ (Confidence Threshold Reached >= 0.92) [UNIFIED MASTER NODE in Neo4j] (:Person {id: "PERSON_MASTER_771", canonical_name: "Alexandre Vance", aliases: [...]})

Merging Fragmented Nodes in Neo4j

When two nodes are identified as the same real-world entity, you do not simply delete one. You must merge their relationships so no transaction history is lost.

In Neo4j, the APOC library provides the mergeNodes procedure to combine nodes while preserving all connected edges:

// Match the two duplicate nodes
MATCH (p1:Person {name: "Alexandre Vance"}), (p2:Person {name: "A. Vance"})
// Merge p2 into p1, redirecting all relationships to p1
CALL apoc.refactor.mergeNodes([p1, p2], {
  properties: "combine",
  mergeRels: true
})
YIELD node
RETURN node;
DevOps Pipeline Architecture
Do not run heavy entity resolution synchronously during live document upload. Perform initial extraction to a staging area in BigQuery or Neo4j, and run an asynchronous batch Entity Resolution pipeline (via Cloud Run or Dataproc) to cluster and merge duplicate entities.
