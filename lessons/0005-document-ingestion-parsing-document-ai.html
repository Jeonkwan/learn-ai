Lesson 0005 • Ingestion & Parsing

Document Ingestion with Cloud Document AI

Why naive PDF extraction corrupts financial tables, and how GCP Document AI preserves spatial geometry.

In financial crime investigations, valuable evidence rarely arrives as pristine UTF-8 text files. It arrives as scanned PDF bank statements, bills of lading in Trade-Based Money Laundering (TBML), and complex multi-column wire ledgers.

Many novice AI projects make a fatal error: they run a simple open-source text scraper (like basic pypdf) and immediately dump the extracted strings into a vector database. Let's see why this creates a disaster in banking data.

The "Table Scramble" Catastrophe

PDF is not a document format; it is a printing instruction stream. It stores commands like "draw character 'A' at coordinates (x=102, y=450)". It has no built-in concept of a table, row, or column.

Naive Text Scraper (Reading Left-to-Right Across Lines): 
Date Beneficiary Amount Currency
09/12 Shell Corp A $450,000 USD
09/13 Luxury Imports $120,000 EUR

Becomes raw text:
"Date Beneficiary Amount Currency 09/12 Shell Corp A $450,000 USD 09/13 Luxury Imports $120,000 EUR"
(If text wraps, lines merge: "09/12 $450,000 Shell Corp A Luxury Imports $120,000")

Result: The connection between the date, the company, and the dollar amount is hopelessly scrambled.

Layout-Aware Extraction (Cloud Document AI): 
| Date  | Beneficiary    | Amount   | Currency |
|-------|----------------|----------|----------|
| 09/12 | Shell Corp A   | $450,000 | USD      |
| 09/13 | Luxury Imports | $120,000 | EUR      |

Result: Markdown table structure preserves cell relationships so the LLM knows exactly who received $450,000.

How Google Cloud Document AI Solves This

Cloud Document AI uses vision-language computer vision models (such as LayoutLM) to visually perceive the page layout just like a human investigator. It classifies regions into paragraphs, headers, and grid tables.

Choosing the Right Processor Type in GCP

  • OCR Processor: Fast, economical text recognition for pure narrative memos, court depositions, and emails.
  • Form Parser (FORM_PARSER_v2): Detects key-value pairs (e.g., "Beneficiary Name:" → "Apex Holdings Ltd") and structured tabular grids. Essential for invoices and customs declarations.
  • Specialized Processors: Pre-trained models tailored for specific banking documents (e.g., BANK_STATEMENT_PROCESSOR, INVOICE_PROCESSOR).

Triggering Document AI from Bash / DevOps Pipelines

In an event-driven GCP pipeline, a Cloud Storage upload triggers a Cloud Run worker that invokes the Document AI processor via REST:

# Process a trade invoice PDF via Document AI REST API
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json; charset=utf-8" \
  "https://${LOCATION}-documentai.googleapis.com/v1/projects/${PROJECT_ID}/locations/${LOCATION}/processors/${PROCESSOR_ID}:process" \
  -d '{
    "rawDocument": {
      "content": "'$(base64 -i customs_declaration.pdf)'",
      "mimeType": "application/pdf"
    }
  }'

The response returns a structured JSON payload containing coordinates, text blocks, and parsed table cells that we can serialize directly into clean Markdown tables before chunking.
