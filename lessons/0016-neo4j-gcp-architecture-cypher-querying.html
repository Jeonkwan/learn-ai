Neo4j on GCP & Cypher Querying

Deploying graph infrastructure on Google Cloud and hunting money laundering rings using Cypher patterns.

We now have clean entity triples and resolved nodes. Where does a DevOps engineer run this in Google Cloud, and how do we query it to uncover criminal money rings?

Deploying Neo4j on GCP: Two Architectural Paths

  • Option 1: Neo4j AuraDB on GCP (Fully Managed SaaS): Available through the GCP Marketplace. Google and Neo4j manage the clustering, backups, and autoscaling. Connects securely to your VPC via Private Service Connect (PSC) without exposing public IPs.
  • Option 2: Self-Managed Neo4j on GKE (Google Kubernetes Engine): Deploy Neo4j Enterprise as a StatefulSet on GKE using Regional Persistent Disks (SSD). Offers maximum configuration control for air-gapped banking compliance.

Cypher: The Visual Pattern Language

Cypher uses visual ASCII art to represent graph topology: (nodes in parentheses) and -[relationships in brackets]->.

Pattern 1: Detecting Circular Money Laundering Rings

Criminals frequently execute layering loops: sending funds through three or four intermediate accounts across different banks, only to return the cleaned money back to the original controller:

MATCH path = (origin:Account)-[:TRANSFERRED*2..6]->(origin) RETURN [n in nodes(path) | n.iban] AS account_ring, length(path) AS total_hops, nodes(path)[0].owner AS beneficiary;

Notice the *2..6 syntax: this instructs Neo4j to find paths between 2 and 6 hops long where the start and end account are the exact same node!

Pattern 2: Detecting "Shell Company Factories"

A classic red flag in financial crime is finding a single modest address (or corporate secretarial agent) that is registered as the official headquarters of dozens of unrelated holding companies:

MATCH (c:Company)-[:REGISTERED_AT]->(addr:Address) WITH addr, count(c) AS company_count, collect(c.name) AS shell_names WHERE company_count >= 20 RETURN addr.street, addr.city, company_count, shell_names ORDER BY company_count DESC;

Pattern 3: Sanctions Proximity Screening (3 Degrees of Separation)

An investigator needs to know if Account #9901 has any financial proximity to a sanctioned entity within 3 hops:

MATCH path = (target:Account {iban: "GB88CHAS9901"})-[:TRANSFERRED*1..3]-(sanctioned:Person {is_sanctioned: true}) RETURN path, [r in relationships(path) | r.amount] AS transfer_amounts;
