# Mission: Architecting Unstructured Data & Knowledge Retrieval for LLMs (Financial Crime Investigation)

## Why
Equip a DevOps engineer with deep architectural intuition to evaluate, design, and make sound technical decisions on storing and feeding complex unstructured data (investigative reports, PDFs, entity networks) to LLMs in enterprise cloud environments.

## Success looks like
- Confidently evaluate when to use Vector RAG vs. Graph databases (Neo4j) vs. Hybrid GraphRAG for complex unstructured domain data.
- Clearly explain the end-to-end data pipeline: ingestion, chunking, embedding generation, vector indexing, graph modeling (entities & relationships), and retrieval.
- Design an end-to-end architecture diagram and infrastructure stack (grounded in GCP and enterprise best practices) for an AML/financial crime intelligence assistant.
- Identify the performance bottlenecks, hallucination failure modes, cost drivers, and security/governance considerations of each storage and retrieval pattern.

## Constraints
- Engineering background is in DevOps, bash/shell scripting, and GCP infrastructure rather than heavy software application development.
- Prioritize architectural clarity, data flow, operational trade-offs, and system design over deep algorithmic/mathematical proofs or full-stack web UI code.
- Ground examples in the financial crime investigation domain (SAR narratives, entity graphs, transaction networks, policy documents).

## Out of scope
- Training foundation LLMs from scratch or low-level CUDA optimization.
- Complex frontend web application development.
- Pure statistical machine learning theory unrelated to retrieval and embeddings.
